What is true and checked today

  • The US disc. The first game is ported from the US disc of Tools of Destruction, BCUS98127. Other regions are untested.
  • Tested under Proton on Linux. Every test run so far has been the Windows program under Proton on Linux (the setups are in the table below). It has not been run on Windows itself yet.
  • One runtime for the series. All the games share one runtime and one set of tools, with one program per game. The PPU code of A Crack in Time and Into the Nexus is already lifted to C with the same tools. A Crack in Time also builds into its own program, not tested yet; Into the Nexus is not linked yet.
  • Fixes sent upstream. General fixes found while porting go back to ps3recomp as pull requests: #401, #408, #415, #429 and the documentation change #405, all merged.

You need your own copy of the game. This repository contains only the port: source code, patches to the recompiler, tools and documentation. It contains no game code, data, assets, keys or firmware, and it never will.

Known issues

There is no settings menu yet. Alt+Enter toggles fullscreen; pads are read through SDL3.

Known issues in Tools of Destruction (on the build in the table above):

  • At Fastoon's spaceport, reflections are far too strong and a HUD prompt shows mirrored in the scene.
  • The picture flickers inside one cave on Fastoon.
  • Level loads stall while graphics pipelines are built; the game's own graphics-stall notice can show during them.
  • The game has not been played through, so later levels are untested.

About

A native Windows port of the PS3 Ratchet & Clank games, made by static recompilation on ps3recomp; the first game, Ratchet & Clank Future: Tools of Destruction, needs your own copy of its US disc, BCUS98127 (disc version, no update).

How it works, briefly

  • PPU (main CPU code): lifted to C ahead of time by ps3recomp and compiled into the Windows program, so no CPU emulator runs for the main game code at play time.
  • SPU (Cell co-processor code): the game's SPU programs (its job modules and two collision programs) are found in your EBOOT.elf and lifted to C the same way, by the build steps; the runtime runs them as compiled code.
  • Graphics: the game's RSX command stream is translated to Direct3D 12 as it runs, by the ps3recomp runtime.
  • System software: the PS3 libraries the game calls are reimplemented on PC APIs by the same runtime.

The shared runtime is ps3recomp's; this repository holds the port's own patches and tools.

How AI was used

This port is developed by one maintainer with AI coding agents. The agents write code, tests and documentation under the maintainer's direction; the maintainer decides what is done, reviews the changes and merges them. Every claim in the docs is dated and says how it was measured; guesses are marked ASSUMPTION:. The PS3 emulator RPCS3 is used as a reference to read, never as code to copy.

Roadmap on GitHub

Install

Nothing is released as a program: you build it yourself from your own copy of the game.

Download. The first release is v0.1.0, a pre-release, on this repository's GitHub Releases page. It is source code only: there is no installer and no ready-made game program, because the program is generated from your own copy of the game. Every release stays a pre-release until v1.0.0. No game code, assets or keys are ever shipped or downloaded here.

Steps: build the program from source with your own copy (docs/BUILDING.md), then start tods.exe with the path of your decrypted EBOOT.elf.

Where your data goes. Nothing is installed and no launcher exists yet. The developer build reads your own game folder and keeps its saves and caches in folders you point it at (the test scripts use work/). Proper locations for saves, settings and caches: not yet.

What goes online. The port has no update check, no crash reporting and no telemetry. Online play of the original game is not supported and untested. Whether the shared runtime opens network connections for the game's own network calls has not been checked for this title yet.
