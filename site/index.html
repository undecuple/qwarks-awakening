What is true and checked today

  • The US disc. The first game is ported from the US disc of Tools of Destruction, BCUS98127. Other regions are untested.
  • Tested under Proton on Linux. Every test run so far has been the Windows program under Proton on Linux (the setups are in the table below). It has not been run on Windows itself yet.
  • One runtime for the series. All the games share one runtime and one set of tools, with one program per game. The PPU code of A Crack in Time, All 4 One, Full Frontal Assault and Into the Nexus is already lifted to C with the same tools. A Crack in Time and Into the Nexus also build into their own programs and show their intros, at about one frame per second; the others are not built yet.
  • Fixes sent upstream. General fixes found while porting go back to ps3recomp as pull requests: #401, #408, #415, #429 and the documentation change #405, all merged.

You need your own copy of the game. This repository contains only the port: source code, patches to the recompiler, tools and documentation. It contains no game code, data, assets, keys or firmware, and it never will.

Known issues

There is no settings menu yet. Alt+Enter toggles fullscreen; pads are read through SDL3.

Known issues in Tools of Destruction (on the build in the table above):

  • At Fastoon's spaceport, reflections are far too strong and a HUD prompt shows mirrored in the scene.
  • The picture flickers inside one cave on Fastoon.
  • Level loads stall while graphics pipelines are built; the game's own graphics-stall notice can show during them.
  • The game has not been played through, so later levels are untested.

About

A native Windows port of the PS3 Ratchet & Clank games, made by static recompilation on ps3recomp; the first game, Ratchet & Clank Future: Tools of Destruction, needs your own copy of its US disc, BCUS98127 (disc version, no update).

How it works, briefly

  • PPU (main CPU code): lifted to C ahead of time by ps3recomp and compiled into the Windows program, so no CPU emulator runs for the main game code at play time.
  • SPU (Cell co-processor code): the game's SPU programs (its job modules and two collision programs) are found in your EBOOT.elf and lifted to C the same way, by the build steps; the runtime runs them as compiled code.
  • Graphics: the game's RSX command stream is translated to Direct3D 12 as it runs, by the ps3recomp runtime.
  • System software: the PS3 libraries the game calls are reimplemented on PC APIs by the same runtime.

The shared runtime is ps3recomp's; this repository holds the port's own patches and tools.

How AI was used

This port is developed by one maintainer with AI coding agents. The agents write code, tests and documentation under the maintainer's direction; the maintainer decides what is done, reviews the changes and merges them. Every claim in the docs is dated and says how it was measured; guesses are marked ASSUMPTION:. The PS3 emulator RPCS3 is used as a reference to read, never as code to copy.

Changelog

Newest first. The full file is on GitHub.

[0.2.0] - 2026-11-03 (pre-release)

Added

  • A log file per game: each game writes logs/<game>/ beside its program, with a header (port version, game and title ID, Windows or Wine/Proton version, CPU, memory, settings in use) and the reason the game ended; a crash also leaves a crash report and a minidump there. Your user name and home folder are removed from them. Checked with Tools of Destruction under Proton on 2026-11-03: a five-minute run and a forced crash.
  • A launcher preview in launcher/ (SDL3 and Dear ImGui): it lists all eight games with their state, shows which of your files it found, and has screens for choosing the folders by hand (seen in screenshots on Linux; not tried on Windows yet). It does not build or start a game yet.
  • The launcher preview as a Windows x64 download: the release page carries Qwarks-Awakening-0.2.0-launcher-windows-x64.zip, built from this repository by the release workflow on GitHub. It holds the launcher, SDL3, its fonts, the file-finding tool with the Python that runs it (nothing else to install) and the licences; no game files and no game program. On the first start it looks in RPCS3's usual folders and writes its game list.
  • Offline behaviour for the network and PlayStation Network functions the later games import (HTTP, SSL, network sockets and status, PSN sign-in, friends, scores, matching, store): they answer as a console with no network connection does. Host-tested; no game has run with them yet.
  • Issue forms ask which game a report is about.
  • Keyboard controls for Tools of Destruction, with default keys for every pad button, played by hand under Proton on 2026-11-03. Mouse look is in the code but off by default until it has been tested.
  • Settings per game: each game keeps its own keybinds.ini, display.ini and settings.ini in its own folder, so keys and display choices for one game do not change another.

Changed

  • A Crack in Time (1.20 update) now starts and shows its intro: Qwark's cinematic is drawn on screen. It runs very slowly (about one frame per second) and is not playable. Three changes got it there: a lock-free queue push between the main processor and the SPU tasks now wakes the waiting task; an error raised inside the game's Lua scripts now returns to the script's error handler instead of ending the game after seven seconds; and an SPU task scheduler that the game ships as SPU code, and that is not translated yet, now runs in the runtime's SPU interpreter.
  • Into the Nexus (1.01 update) is built for the first time and shows its intro, the Polaris News broadcast with subtitles, at the same slow speed; not playable.
  • Tools of Destruction was checked with these changes: a new game and a saved game, five minutes each, without a crash.
  • The PPU code of Quest for Booty, Ratchet: Deadlocked HD and the Ratchet & Clank Collection's programs is lifted, and Quest for Booty's SPU programs are found and translated; none of these is built yet.

Roadmap on GitHub

Install

No game program is released: you build it yourself from your own copy of the game. The launcher preview is a download.

Download. Releases are pre-releases on this repository's GitHub Releases page. Since v0.2.0 each one has a launcher preview for Windows (Qwarks-Awakening-<version>-launcher-windows-x64.zip, with Python included): it lists the games and the files it finds, and does not build or start a game yet. There is no installer and no ready-made game program, because the program is generated from your own copy of the game. Every release stays a pre-release until v1.0.0. No game code, assets or keys are ever shipped or downloaded here.

Steps: build the program from source with your own copy (docs/BUILDING.md), then start tods.exe with the path of your decrypted EBOOT.elf.

Where your data goes. Nothing is installed yet. The developer build reads your own game folder and keeps its saves and caches in folders you point it at (the test scripts use work/). Each game writes its log, and a crash report if it crashes, to logs/<game>/ beside the program; your user name and home folder are removed from them, so a log can be attached to an issue as it is. Proper locations for saves, settings and caches: not yet. A launcher preview is in launcher/: it lists the games and their state and has screens for choosing where your files are (not tried on Windows yet); it does not build or start a game yet.

What goes online. The port has no update check, no crash reporting and no telemetry. Online play of the original game is not supported and untested. Whether the shared runtime opens network connections for the game's own network calls has not been checked for this title yet.
