Known issues

There is no in-game settings menu yet. Each game keeps its own keybinds.ini, display.ini and settings.ini. Display and control settings for all games go in shared/display.ini and shared/keybinds.ini in the data folder. A key in a game's own file wins. Alt+Enter toggles fullscreen, and each game remembers its window's place and size.

Controllers: pads are read through SDL3.

  • DualShock 4: played by hand (Tools of Destruction, 2026-10-22).
  • Keyboard: default keys for every pad button, played by hand (Tools of Destruction, 2026-11-03).
  • Mouse look: off unless [mouse] look = on is set in keybinds.ini; checked in scripted runs only.
  • Other pads SDL3 supports (Xbox, DualSense, Switch Pro and others): not tested.

Known issues in Tools of Destruction:

  • The picture flickers inside one cave on Fastoon.
  • Level loads stall while graphics pipelines are built; the game's own graphics-stall notice can show during them.
  • The quit entries of the pause menu (off unless RC_PAUSE_QUIT=1) are drawn below the menu's box, and QUIT TO MAIN MENU loads the last save again.
  • The game has not been played through, so later levels are untested.

All known issues, with how and when each was measured: docs/KNOWN_ISSUES.md.

About

Bring your own game. This repository holds only the port: source code, patches to the recompiler, tools and documentation. It contains no game code, game data, assets, keys or firmware, and it never will. To build a game you need your own copy of it and the decrypted EBOOT.elf made from that copy (What you need).

How it works, briefly

  • PPU (main CPU code): lifted to C ahead of time by ps3recomp and compiled into the Windows program. No CPU emulator runs for the main game code at play time.
  • SPU (Cell co-processor code): the build finds the game's SPU programs in your EBOOT.elf and lifts them to C the same way. A program not lifted yet runs in an interpreter.
  • Graphics: the ps3recomp runtime translates the game's RSX command stream to Direct3D 12 as it runs.
  • System software: the same runtime reimplements the PS3 libraries the game calls on PC APIs.

Native Windows source builds fetch the pinned llvm-mingw, CMake and Ninja archives and run through PowerShell and Python; Linux builds use the Nix flake (nix develop, nix develop .#win for the MinGW-w64 cross compiler). The recompiler is the third_party/ps3recomp submodule, with this port's changes in port/patches/. Steps: docs/BUILDING.md.

How AI was used

This port is developed by one maintainer with AI coding agents. The agents write code, tests and documentation under the maintainer's direction. The maintainer decides what is done, reviews the changes and merges them. Run results in the docs give their date and how they were measured; guesses are marked ASSUMPTION:. The PS3 emulator RPCS3 is used as a reference to read, never as code to copy.

Steps

  1. Download Qwarks-Awakening-<version>-setup-windows-x64.exe from the Latest release. You now have one setup file.
  2. Run it. The program is not signed, so Windows may show "Windows protected your PC". Choose "More info", then "Run anyway". The setup's welcome page opens.
  3. Click Next, Next, Install. The default folder is %LOCALAPPDATA%\Programs\Qwark's Awakening; you can pick another one. No administrator rights are needed. The last page says "Setup is done".
  4. Click Finish with "Start Qwark's Awakening" ticked. The launcher opens. On its first start it looks for your games in RPCS3's usual folders, reading only, and writes library.json in the install folder.
  5. Pick a game and click Build. If a game is missing, add its folder under Settings, Locations. The build takes a while. When it ends, the launcher says "Finished: ... is built and ready to play." Click Play.

Portable (no install): each launcher release also has two zips. The full build zip holds the same files as the setup. The launcher zip holds only the launcher; it asks before it downloads the build kit on your first Build. Unpack the whole folder, then start Qwarks-Awakening-launcher.exe. SHA256SUMS on the release page lists the checksum of every file.

Linux: download qwarks-awakening-launcher-<version>-linux-x86_64.tar.gz from the same release, unpack it and run ./install.sh in its folder. It installs the launcher for your user (no administrator rights) with a menu entry; install.sh --uninstall removes it again. Or take qwarks-awakening-launcher-<version>-x86_64.AppImage, the same launcher in one file that runs where you keep it: chmod +x it and start it (on NixOS: appimage-run). docs/LINUX.md has the details and the Proton choice.

Uninstall from Windows Settings, Apps, or from the Start menu. The uninstaller removes the program files. It asks before it deletes your library, your built games with their saves, and the logs. Then it asks before it deletes the games' settings. Both answers default to No.

Where your data goes. The launcher keeps your library (library.json), built games, build files and logs in its install folder. Each game keeps its saves in gamedata\ beside its program unless you choose a saves folder in Settings, Locations. The games' settings are in %APPDATA%\Qwark's Awakening. Each game writes its log, and a crash report if it crashes, to logs/<game>/ beside its program. Your user name and home folder are removed from them.
